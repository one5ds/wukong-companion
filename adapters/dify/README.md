# Dify / Coze / 扣子 等平台接入

这些平台的共同结构是：**系统提示词 + 知识库 + 开场白**。本仓库正好一一对应。

## 一、系统提示词

直接把 [`core/system-prompt.md`](../../core/system-prompt.md) 粘进「角色设定 / Instructions」。

Dify 的「提示词编排」里建议：

```
{{system_prompt}}

## 知识检索结果
{{context}}

若检索结果与用户问题无关，忽略它，不要强行引用。
```

## 二、知识库该怎么建（重点）

### 不要做的事

❌ **不要把原书 PDF 整个上传成知识库。**

原因有两个，第二个更致命：

1. 版权：知识库可能被平台用于其他用途，且用户可通过提示词诱导输出原文。
2. **产品效果**：365 页对话体切片后，检索出来的往往是"勿空：…… 无师：……"的残缺片段。模型拿到这种片段，会开始**模仿原文句式**，输出变得古板、书面、爱说"善哉"。这是最常见的翻车方式。

### 应该做的事

上传作者自己写的教法文件：

| 文件 | 切片建议 | 作用 |
|---|---|---|
| `knowledge/quotes.md` | 整篇不切，或按 `###` 切 | 语气校准 |
| `knowledge/INDEX.md` | 不切 | 主题路由（判断用户属于哪个月的主题） |
| `core/method.md` | 按 `##` 切 | 教法规则 |
| 自建的「主题卡」（见下） | 一卡一切片 | 检索主命中 |

### 自建「主题卡」的格式

十二个主题各建一张卡，不要把原文搬进来，只写**结构**：

```markdown
# 主题卡：烦恼与痛苦（一月）
核心命题：烦恼来自想不生烦恼的执着。
常见入口：焦虑、失眠、反复想一件事、觉得自己不够好。
四段位落点：多数人在第一段（不计较）与第二段（理解）之间。
可用意象：跟屁虫、镜子。
推荐反问：放大式 / 归因式。
避开：不要劝"放下"，这个词在此主题下是压迫。
```

十二张卡 ≈ 2000 字，检索精度远高于全书切片。

## 三、开场白与建议问题

```
开场白：今天是你余生的第一天，有什么想聊聊的吗？烦恼也好，困惑也好，我陪你一起看看。

建议问题：
- 最近总是很焦虑，心静不下来，该怎么办？
- 怎么才能不那么在意别人的眼光和评价？
- 有件事我一直放不下，但说不清是什么。
```

## 四、参数

| 参数 | 建议 | 理由 |
|---|---|---|
| 温度 | 0.7–0.9 | 低了说教，高了编禅语 |
| 最大回复长度 | 300 tokens | 硬约束 5 句 |
| 上下文轮数 | ≥ 10 | 短回复依赖记忆 |
| 知识库 Top-K | 2–3 | 多了会串主题 |
| 相似度阈值 | 0.5 以上 | 宁可检索不到，不要检索错 |

## 五、上线前必做

跑一遍 [`evals/`](../../evals/)，特别是 `crisis-*` 与 `advice-*` 两类用例。
涉及情绪支持的产品，**安全用例不过，不上线**。
