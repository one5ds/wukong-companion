# 设计决策记录 · Design Decisions

> 目的：让后来者（包括三个月后的你自己）不必重新踩一遍坑。

## ADR-001 · 形态：Agent，不是 Skill，也不是纯 RAG 问答

**状态**：已采纳（v1.0）

### 背景

《勿空与无师》是一本对话录。要把它变成 AI 产品，有四条路：

| 方案 | 做法 | 成本 | 效果 |
|---|---|---|---|
| A. 纯 RAG 问答 | 全书切片进向量库，检索后回答 | 低 | 像在查词典 |
| B. Skill | 把教法写成任务流程，被调用时执行 | 低 | 像在走流程 |
| C. Agent 人格 | prompt 定义"是谁 + 怎么说话"，持续对话 | 中 | 像在跟人说话 |
| D. 微调模型 | 用全书构造 SFT 数据 | 高 | 像，但不可控、不可解释 |

### 决策

**主体用 C（Agent），把 A 的知识地图作为辅助索引，B 作为可选插件，暂不做 D。**

### 理由

1. **A 的失败是结构性的。** 检索返回的是片段，模型会**模仿片段**。原文是"勿空：… 无师：…"的书面对话体，模型学到的是句式，不是智慧。用户会得到大量"善哉""如是"——这是最常见也最难修的翻车。
2. **B 的失败是时机性的。** Skill 由任务触发。用户说"我很累"的时候，系统在判断"这是不是个任务"，这个判断本身就是伤害。
3. **C 的关键不在知识量，在约束。** 陪伴的质量由"不说什么"决定：不诊断、不列清单、不承诺、不超过 5 句。这些用 prompt 约束最直接、可迭代、可评测。
4. **D 现在不值得。** 见 ADR-002。

### 后果

- 需要人工把"教法"写出来（`core/method.md`），不能靠堆语料。
- 需要评测集来防止 prompt 漂移。
- 好处：改一句话就能改行为，不需要重训。

## ADR-002 · 不做微调（至少现在不做）

**状态**：已采纳

### 理由

1. **数据量不够且不该公开。** 全书 300 余则对话，去掉标点约 13 万字。SFT 通常需要数千至数万条高质量样本，且要防止"背原文"——而背原文恰恰是版权红线。
2. **微调会降低可控性。** 现在改一句 prompt，5 句话的约束立刻生效；微调模型的"5 句"是统计倾向，不可解释、不可定点修。
3. **微调模型爱模仿口癖。** 对话体微调后，模型会输出"勿空：""无师："这类角色标签，甚至自问自答。
4. **成本与收益不匹配。** 一个精心写的 2400 字 prompt + 24 条评测，在"短句 + 反问"这个窄任务上，效果已接近微调，成本差两个数量级。

### 什么情况下才值得做

- 有明确的产品指标（如人工评分提升 ≥ 15%）；
- 有著作权人书面许可，且训练数据**不公开**；
- 有 ≥ 2000 条人工标注的高质量对话（而不是从书里直接切）。

## ADR-003 · 为什么硬性限制「≤ 5 句」

**状态**：已采纳

### 背景

最初版本不限长度。实测下来，模型会写 200–400 字的"温暖的建议"，读完很舒服，但**用户没有变化**。

### 判断

> 长回复是在满足 AI 自己（显得周到），不是在帮用户。

短回复逼出三件事：

1. **必须先判断**——5 句装不下所有情况，所以必须选一个最要紧的角度，这迫使模型做"段位判断"。
2. **必须留白**——话说不完，对方才有空间接。陪伴的节奏由对方掌握。
3. **必须克制**——不能既接情绪又给方法又做升华。只能选一个动作。

### 实现

软约束（prompt 里写"≤5 句"）+ 硬约束（`max_tokens=300`）双管。只有软约束，模型会偶尔破例；只有硬约束，会截断在半句话上。

## ADR-004 · 版权：仓库不放原书全文

**状态**：已采纳（关键决策）

### 背景

最省事的做法是把 PDF 一起 commit 进 `assets/`，任何人 clone 就能用。

### 决策

**不做。仓库只保留：主题地图（页码索引）、18 则短摘录、作者自撰的教法。**

### 理由

1. **公开仓库 = 向公众提供作品。** 免费不免责，这不是合理使用。
2. **出版合约可能已授予专有出版权 / 信息网络传播权**，作者本人也未必有权自行全文公开。
3. **开源许可不可撤回。** MIT / CC 一旦发布，任何人可永久使用。删掉文件也删不掉 git 历史与已有的 fork。这是不可逆的错误，必须事前避免。

### 后果

- 用户需要自行购买/获取原书才能读全文——这本来也是对的。
- 反而提高了项目的**正当性**：它是"教法开源"，不是"盗版分发"。
- 若后续要做 RAG，需要用户自备正版电子书，仓库只提供切分脚本（不含内容）。

## ADR-005 · 评测里必须放「危机用例」

**状态**：已采纳

### 理由

生活禅的回应方式（"烦恼即菩提""无常""放下"）在**情绪危机场景下是危险的**。一个把"我想死"解读成"你在执着于解脱"的系统，会真的伤人。

所以评测里 `crisis-01/02/03` 三条是**一票否决**：安全项不得分，整条不通过，不论其他维度多高。

### 具体约束

- 危机场景**禁用任何比喻**（比喻会显得轻慢）。
- 允许超过 5 句（安全优先于风格）。
- 必须直接问"你现在安全吗"——这不是冒犯，是标准做法。
- 必须给出可执行的求助路径，而不是"去找人聊聊"。

## ADR-006 · 中文优先，英文不是翻译

**状态**：已采纳（v1.2 完成）

### 已知问题

文言感的短句直译成英文会变成"鸡汤语录"。英文世界里对应的语感不是"禅意"，是**具体的、克制的、略带幽默的日常语言**（更接近 Stoicism 的现代写作，而不是 New Age）。

### 落地做法

英文版全部**重写**，不逐句对译。四条具体规则：

1. **删掉四字格。** 中文靠对仗取胜（"痛而不言，笑而不语"），英文里对仗会变成墓志铭。英文版改成直说：*"Pain without speaking. Laughter without explaining."* —— 保留意思，放弃韵律。
2. **禁词表。** 不用 journey、universe、sacred、embrace、hold space、energy、vibrate。这些词一出现，读者立刻归类为"灵修内容"。
3. **短句靠句号，不靠逗号。** 中文的逗号长句在英文里会散掉。英文版把每个逗号尽量换成句号。
4. **保留具体的器物。** 镜子、火车、跟屁虫（→ a dog that follows you）、租期、地铁站。英文读者对抽象词免疫，对具体物有反应。

### 后果

- 维护成本翻倍：改中文卡要同步改英文卡，且不能直接翻译。
- 但英文版不是"中文版的附属品"——它是给另一群读者的**独立重写**，可以独立演进。
