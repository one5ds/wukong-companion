# 十二张主题卡 · Themes

> 这是本项目的**检索层**。
> `core/method.md` 讲「怎么说话」，这十二张卡讲「在什么话题上说什么」。
>
> **English edition:** [themes/en/](./en/) — all twelve rewritten, not machine-translated.

---

## 为什么要有主题卡

如果把原书 300 余则对话直接切片进向量库，会遇到三个问题：

1. **切片残破** —— 检索出来常是"勿空：…… 无师：……"的半句话，模型拿到会模仿句式。
2. **检索串味** —— 「放下」这个词在五个主题里都出现，一检索就串。
3. **无法约束** —— 原文里没有"这个主题下不要说什么"，模型不知道禁区在哪。

主题卡是**人工提炼的结构**：一卡一主题，含命题、段位、意象、反问、禁区。它比原文短，比原文准。

## 卡片结构

每张卡固定六段，**格式统一是为了能被检索稳定命中**：

```
一句话            ← 这张卡的摘要，也是最好的检索目标
人真正在问什么     ← 4 行「他说的 / 他其实在问」对照表
核心命题          ← 8–14 条，每条以原书篇名为锚点，后接一句白话解释
段位落点          ← 这个主题下的人多在第几段，信号是什么
可用意象          ← 3–5 个，标注使用限制
推荐反问          ← 3 条，标注类型（放大 / 反转 / 换位 / 归因 / 假设）
常见误答（避开）   ← 5 条禁区，这是最有价值的一段
关联主题          ← 什么时候该转到别的卡
```

## 怎么用在 RAG 里

| 做法 | 说明 |
|---|---|
| **一卡一 chunk** | 不要按行切。一张卡是一个完整语义单元，切开就散。 |
| **Top-K = 2** | 一张就够。K 大了会串主题。 |
| **先路由再检索** | 先用 12 个"一句话"做粗分类，选定主题后再取该卡全文。比直接向量检索准得多。 |
| **只放卡片，不放原文** | 原文切片见 [../INDEX.md](../INDEX.md) 的理由说明。 |

Dify / Coze 的具体配置见 [adapters/dify/README.md](../../adapters/dify/README.md)。

## 和 method.md 的分工

```
用户说了一句难受的话
   │
   ├─ 第一步：判断落在哪张卡（12 选 1）      ← themes/
   ├─ 第二步：判断他在第几段（4 选 1）        ← method.md
   ├─ 第三步：选一个反问类型（5 选 1）        ← method.md
   └─ 第四步：检查是否踩到这张卡的禁区（5 条） ← themes/
```

**先卡，后法。** 顺序反了，就会变成一个到处讲"放下"的复读机。
